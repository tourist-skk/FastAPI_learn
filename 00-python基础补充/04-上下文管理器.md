# 04-上下文管理器

建议先阅读[同步与异步](03-同步与异步.md)。本篇从普通 `with` 入手，再解释 `async with` 和资源的进入、退出。

第 16 节分文件示例将生命周期代码放在 `main_sqlite.py`；当前项目也可以将它与数据库配置合并到 `database_sqlite.py`。下面说明其中的 `async with`，装饰器用法见[下一篇](05-asynccontextmanager装饰器.md)。

## 1. 先理解普通上下文管理器

上下文管理器用于管理资源的“进入”和“退出”。最常见的例子是打开文件：

```python
with open("message.txt", "w") as file:
    file.write("Hello")
```

执行过程是：

1. 进入 `with` 时打开文件。
2. 将打开的文件对象赋给 `file`。
3. 执行缩进代码。
4. 离开 `with` 时自动关闭文件。

即使缩进代码发生异常，退出处理仍然可以执行。因此，上下文管理器适合管理文件、数据库连接、事务和网络连接等需要释放的资源。

## 2. 什么是异步上下文管理器

异步上下文管理器与普通上下文管理器的目的相同，但它在进入或退出时可以执行需要等待的异步操作。

普通上下文管理器使用 `with`：

```python
with resource_manager() as resource:
    use(resource)
```

异步上下文管理器使用 `async with`：

```python
async with async_resource_manager() as resource:
    await use(resource)
```

从底层协议来看：

- 普通上下文管理器实现 `__enter__()` 和 `__exit__()`。
- 异步上下文管理器实现 `__aenter__()` 和 `__aexit__()`。

`async with` 只能写在 `async def` 函数中。

## 3. `engine.begin()` 是异步上下文管理器

建表代码中包含：

```python
async with engine.begin() as connection:
    await connection.run_sync(Base.metadata.create_all)
```

这段代码的执行过程是：

1. `engine.begin()` 创建数据库异步上下文管理器。
2. 进入代码块时获取数据库连接并开启事务。
3. `as connection` 将连接对象赋给 `connection`。
4. 使用该连接执行建表。
5. 离开代码块时结束事务并释放连接。

如果代码块正常结束，事务会提交；如果代码块抛出异常，事务会回滚。

## 4. FastAPI 是异步上下文管理器吗

FastAPI 本身不是异步上下文管理器：

```python
app = FastAPI()
```

`app` 是一个 FastAPI 应用对象，也是一个 ASGI 应用。FastAPI 可以接收一个异步上下文管理器，用它管理应用的启动和关闭：

```python
app = FastAPI(lifespan=lifespan)
```

这里各对象的关系是：

- `FastAPI`：Web 框架提供的应用类。
- `app`：创建出来的应用对象。
- `lifespan`：传给 FastAPI 的生命周期函数。
- `lifespan(app)`：被调用后产生异步上下文管理器。
- FastAPI：在应用启动时进入该上下文，在应用关闭时退出该上下文。

因此，`async def` 路由函数也不等于异步上下文管理器。一个对象只有支持异步上下文管理协议，才能写在 `async with` 后面。
