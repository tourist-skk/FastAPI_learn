# 01-类型注解

本篇解释变量、函数参数和返回值的类型注解，并沿用第 16 节的数据库代码作为例子。涉及数据库引擎的片段可对照[配置示例](06-SQLite建表与启动排查.md)。

函数注解示例中的 `Path` 需先导入：

```python
from pathlib import Path
```

## 1. 什么是类型注解

类型注解用于说明变量、函数参数或函数返回值预期是什么类型。

```python
username: str = "Tom"
age: int = 18
prices: list[float] = [9.9, 12.5]
```

冒号后面是类型，等号后面才是实际赋给变量的值：

```text
变量名: 预期类型 = 实际值
```

类型注解主要有以下作用：

- 让阅读代码的人更容易理解数据类型。
- 让编辑器提供更准确的代码提示。
- 让 mypy、Pyright 等工具提前发现类型错误。
- 让某些框架在运行时读取类型信息。

## 2. 变量类型注解

`database_sqlite.py` 中的代码：

```python
engine: AsyncEngine = create_async_engine(
    DATABASE_URL,
    echo=True,
)
```

可以分为三部分理解：

- `engine`：变量名。
- `AsyncEngine`：说明期望 `engine` 保存一个异步引擎对象。
- `create_async_engine(...)`：真正创建对象并返回结果。

类型注解不会创建引擎，真正创建引擎的是等号右边的函数调用。删除注解后，代码通常仍能运行：

```python
engine = create_async_engine(
    DATABASE_URL,
    echo=True,
)
```

保留 `AsyncEngine` 的好处是，编辑器能更准确地提示 `engine` 有哪些属性和方法，也能检查错误赋值。

## 3. 函数类型注解

函数参数和返回值也可以添加类型注解：

```python
def build_database_url(database_file: Path) -> str:
    return f"sqlite+aiosqlite:///{database_file.as_posix()}"
```

- `database_file: Path`：参数应该是 `Path` 对象。
- `-> str`：函数应该返回字符串。

没有返回值的函数可以写成 `-> None`：

```python
def show_path(database_file: Path) -> None:
    print(database_file)
```

## 4. 类型注解不会自动限制运行时类型

普通 Python 类型注解默认不会强制检查类型：

```python
count: int = 10
count = "十"

print(count)  # 可以运行，但类型检查工具会提示问题
```

因此，类型注解不等于数据校验。FastAPI、Pydantic 和 SQLAlchemy 等框架可以主动读取部分类型注解并赋予额外作用，但这是框架实现的功能。

例如，`engine: AsyncEngine` 是普通类型提示；模型中的 `id: Mapped[int]` 则会被 SQLAlchemy 读取并用于配置字段映射。
