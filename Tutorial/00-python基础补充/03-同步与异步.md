# 03-同步与异步

本篇先解释同步与异步中常见的基础语法，再讲同步调用、协程函数与对象、任务和事件循环，并提供可独立运行的示例。

## 1. 先认识基本语法：`def`、`async`、`await`、`yield`、`return`

这些词控制着代码如何定义、执行、暂停和结束。下面的完整示例可分别保存为 `.py` 文件运行。

### 1.1 `def` 和 `return`：定义函数、结束这次调用

`def` 用来定义函数。对于不含 `yield` 的普通函数，调用后立即执行函数体；`return` 用来结束这次调用，并把结果交给调用者。

```python
def add(a: int, b: int) -> int:
    return a + b


result = add(2, 3)
print(result)  # 5
```

`return` 后面的普通代码不会继续执行；如果处于 `try...finally` 中，会先执行相应的 `finally` 清理代码。只写 `return` 或执行到函数末尾，都相当于返回 `None`。

### 1.2 `async`：声明异步形式

`async` 是 Python 关键字，常见组合有 `async def`、`async with`、`async for`。它不能单独写成一条“启动异步”的语句。

先看不含 `yield` 的 `async def`：

```python
import asyncio


async def get_number() -> int:
    print("函数体开始执行")
    return 5


coro = get_number()          # 创建协程对象，还没执行函数体
print("协程对象已创建")
result = asyncio.run(coro)   # 运行协程，直到结束
print(result)
```

输出：

```text
协程对象已创建
函数体开始执行
5
```

`async def` 在这里定义的是协程函数，`get_number()` 返回的是协程对象。`async` 不会自动创建线程，也不会让函数自动在后台运行。协程对象需要通过 `await`、`asyncio.run()` 或任务调度等方式驱动，后文会展开解释。

### 1.3 `await`：等待结果，然后继续

`await` 后面必须是**可等待对象**，例如协程对象或 Task。它等待操作完成，并取得结果：

```python
import asyncio


async def get_number() -> int:
    await asyncio.sleep(1)
    return 5


async def main() -> None:
    print("开始等待")
    result = await get_number()
    print(f"拿到结果：{result}")


asyncio.run(main())
```

先输出“开始等待”，约 1 秒后才输出“拿到结果：5”。`result` 最终得到的是 `get_number()` 中 `return` 的值。

当前任务必须等结果，才能继续执行下一行；在等待尚未完成的异步操作时，事件循环可以去运行其他已安排的任务。

**普通 `.py` 脚本中的 `await` 必须放在 `async def` 函数体内**。`await 5`、`await time.sleep(1)` 都不是正确用法：整数和 `time.sleep()` 返回的 `None` 不支持等待。加上 `await` 也不会把一个同步阻塞函数变成异步函数。

### 1.4 `await` 的优先级：为什么不能直接连写结果方法

**属性访问 `obj.attr`、函数／方法调用 `f()`、下标访问 `obj[index]` 的结合优先级，都高于 `await`。** 优先级决定表达式怎样组合；`await` 写在左边，不代表它一定先于后面所有操作生效。[Python 表达式优先级](https://docs.python.org/3/reference/expressions.html#operator-precedence)

例如，项目中的 `db` 是 SQLAlchemy 的 `AsyncSession`，下面这句会报错：

```python
# 错误示例
rows = await db.execute(stmt).mappings().all()
```

Python 对它的解析相当于：

```python
# 仍然错误：await 作用于整个链式表达式
rows = await (db.execute(stmt).mappings().all())
```

实际过程是：

1. 调用 `db.execute(stmt)`，创建一个协程对象，此时还没有得到查询结果 `Result`。
2. 尝试在这个协程对象上访问 `.mappings`。
3. 协程对象没有该方法，抛出 `AttributeError: 'coroutine' object has no attribute 'mappings'`；`.all()` 和等待操作都还没执行到。

因此，这不是“数据库查询完成后，结果没有 `mappings()`”，而是**把结果对象的方法调用到了尚未等待的协程对象上**。还可能伴随 `coroutine ... was never awaited` 警告，因为创建的协程没有被等待。

**写法一：拆成两行，清楚地区分等待与取值。**

```python
result = await db.execute(stmt)  # 等待查询，得到 Result
rows = result.mappings().all()  # 从 Result 读取，得到 RowMapping 列表
```

**写法二：用括号把等待表达式作为一个整体。**

```python
rows = (await db.execute(stmt)).mappings().all()
```

括号的位置很关键：`(await db.execute(stmt))` 先得到 `Result`，外面的 `.mappings().all()` 才在这个结果上调用。这两种正确写法是可替换的方案，不需要执行两遍查询。

本例中，`mappings()` 和 `all()` 是同步读取方法，不能再加一个 `await` 去等待最终列表。异步执行方法与同步结果方法的区别见 [SQLAlchemy 查询结果与取值](09-SQLAlchemy查询结果与取值.md)。

**同样的问题也会出现在普通异步函数中。** 下面是不需要数据库、可以独立运行的例子：

```python
import asyncio


async def get_title() -> str:
    return "python"


async def main() -> None:
    # 先等到字符串，再调用字符串的 upper()
    title = await get_title()
    print(title.upper())  # PYTHON

    # 括号写法，效果相同
    print((await get_title()).upper())  # PYTHON


asyncio.run(main())
```

如果写成 `await get_title().upper()`，就会尝试在协程对象上调用 `upper()` 而报错。同理，若异步函数返回列表，取第一项应写成 `(await get_items())[0]`，而不是 `await get_items()[0]`。

需要在异步函数的**最终返回值**上继续访问属性、调用方法或取下标时，先拆行保存返回值，或者用 `(await 异步调用())` 明确等待的范围。

### 1.5 `yield`：产出一个值，并暂停在这里

`yield` 不只用于异步。普通 `def` 函数体中包含 `yield` 时，它就成为**生成器函数**：调用后得到生成器对象，通过 `next()` 或 `for` 逐步取得它产出的值。

```python
def numbers():
    print("执行第一段")
    yield 10
    print("执行第二段")
    yield 20
    print("执行结束")


gen = numbers()        # 创建生成器对象，还没执行函数体
print(next(gen))       # 执行到第一个 yield，得到 10
print(next(gen))       # 从暂停处继续，到第二个 yield，得到 20
print(next(gen, "没有更多值"))
```

输出：

```text
执行第一段
10
执行第二段
20
执行结束
没有更多值
```

`next(gen)` 表示请求下一个值。每次遇到 `yield`，生成器都会交出一个值并保留执行位置，下次请求时再继续。示例中的最后一次 `next()` 提供了默认值，因此生成器结束时得到“没有更多值”；不提供默认值则会抛出 `StopIteration`。

要区分这三个词：

- `return value`：结束当前执行，交出最终结果。
- `yield value`：交出这一次的值并暂停，后续可以恢复执行。
- `await operation`：等待另一个操作的结果，再继续当前执行。

单独写 `yield` 相当于 `yield None`。它本身不表示“应用已经启动”或“等待应用关闭”；FastAPI 生命周期中的含义来自 `@asynccontextmanager` 和框架对它的使用。

### 1.6 `async def` 中含有 `yield`：异步生成器

`async def` 函数体中含有 `yield` 时，定义的是**异步生成器函数**。调用它得到异步生成器对象，通过 `async for` 逐个取得值：

```python
import asyncio


async def numbers():
    for value in (10, 20):
        await asyncio.sleep(0.1)  # 等待下一条数据准备好
        yield value              # 把这条数据交给使用者


async def main() -> None:
    async for value in numbers():
        print(value)


asyncio.run(main())
```

输出依次为 `10`、`20`。这里 `await` 负责等待，`yield` 负责产出值；二者用途不同。

`async for` 每轮通过异步迭代协议取得下一项，必要时等待；它不会自动并发执行每一轮。不能直接写 `await numbers()`，因为这里得到的是异步生成器对象。异步生成器可以使用不带值的 `return` 提前结束，但不能写 `return 123`。

### 1.7 `async with`：异步地进入和退出一段资源使用过程

`with` 管理资源的进入与退出；`async with` 允许这两个阶段执行异步操作。`as` 将进入时取得的对象绑定到变量。

下面的例子没有数据库依赖，完整展示进入、使用、退出的顺序：

```python
import asyncio
from contextlib import asynccontextmanager


@asynccontextmanager
async def resource():
    print("1. 准备资源")
    try:
        yield "示例资源"
    finally:
        print("3. 清理资源")


async def main() -> None:
    async with resource() as value:
        print(f"2. 使用{value}")


asyncio.run(main())
```

输出顺序为“1. 准备资源 → 2. 使用示例资源 → 3. 清理资源”。进入时执行到 `yield`，其值交给 `value`；退出时继续执行清理代码。

**上面的例子已经写了 `@asynccontextmanager`，因此可以直接使用 `async with resource()`，不需要再加任何步骤。** 这两处代码分别负责：

- `@asynccontextmanager`：在函数定义时包装 `resource`，使调用 `resource()` 得到异步上下文管理器。
- `async with resource() as value`：使用这个已经准备好的管理器，执行进入、代码块和退出的流程。

如果删掉本例的 `@asynccontextmanager`，`resource()` 就会返回原始的异步生成器对象，无法直接用于 `async with`。`async with` 是使用管理器的语法，不会自动把异步生成器转换为管理器。其他已经实现异步上下文管理协议的对象（如 `engine.begin()` 的返回值）则可以直接使用，不需要额外添加这个装饰器。

`async with` 不会自动让代码块中的所有操作都变成非阻塞操作。详细原理见[上下文管理器](04-上下文管理器.md)和[asynccontextmanager 装饰器](05-asynccontextmanager装饰器.md)。

最后区分语法和工具：`async`、`await`、`yield`、`return` 是 Python 关键字；`asyncio.run()`、`asyncio.sleep()`、`asyncio.create_task()` 是标准库提供的函数，`@asynccontextmanager` 是标准库装饰器。

## 2. 同步：当前调用完成后，再执行下一步

同步调用会等待当前函数执行完毕，再继续后面的代码。如果函数中有阻塞操作，当前线程也会跟着等待。

下面用休眠模拟等待数据库或网络响应。可以把完整代码保存为独立脚本运行：

```python
import time


def fetch_data(name: str) -> str:
    print(f"{name} 开始")
    time.sleep(1)  # 阻塞当前线程 1 秒
    print(f"{name} 完成")
    return name


start = time.perf_counter()
fetch_data("A")
fetch_data("B")
print(f"耗时：{time.perf_counter() - start:.1f} 秒")
```

执行顺序是 `A 开始 → A 完成 → B 开始 → B 完成`，总耗时约 2 秒。

同步写法直观，适合简单脚本和同步库。它也可以配合线程处理多个任务；“同步函数”不代表整个程序只能做一件事。

## 3. 异步：等待期间，让其他任务有机会运行

假设有两次互不依赖的查询：A 要等待 2 秒，B 要等待 1 秒。

- 同步顺序执行：先查询 A，等 A 返回后才查询 B，总共约 3 秒。
- 异步并发执行：A 开始等待后，可以开始查询 B；B 约在第 1 秒完成，A 约在第 2 秒完成，总共约 2 秒。

这里减少的是两次查询合起来的总等待时间。A 本身仍然需要 2 秒。要实现这样的执行过程，需要解决两个问题：**如何保存 A 的暂停位置，以及等待 A 时由谁安排 B 执行？** 下面分别解释。

## 4. 区分协程函数、协程对象和任务

### 协程函数：定义“要执行哪些代码”

在下面的例子中，`async def fetch_data(...)` 定义了一个协程函数：

```python
import asyncio


async def fetch_data(name: str) -> str:
    print(f"{name}：进入函数体")
    await asyncio.sleep(1)
    print(f"{name}：等待结束")
    return name
```

`fetch_data` 是函数的名字。定义函数时，只是规定了它的代码，还没有开始执行其中的 `print()`。

### 协程对象：代表这个函数的一次具体执行

调用上面的函数：

```python
coro = fetch_data("A")
```

这行代码没有定义新函数。它调用已有的 `fetch_data` 函数，传入 `"A"`，得到一个**协程对象**，再将这个对象赋给变量 `coro`。

与普通 `def` 函数不同，这次调用不会立即执行函数体，也不会直接返回最终的 `"A"`。协程对象保存这次执行所需的信息，包括参数、局部变量和执行到哪里；开始运行以后，它可以在等待处暂停，再从原位置继续。

因此要区分三个表达式：

- `fetch_data`：协程函数，可多次调用。
- `fetch_data("A")`：调用函数，创建一次新的协程对象。
- `await coro`：运行并等待这次执行，得到函数最终 `return` 的值。

一个已经执行完的协程对象不能再次执行；需要重新调用函数，得到新的协程对象。

下面的完整示例可以直接运行，观察函数体到底何时执行：

```python
import asyncio
import inspect


async def fetch_data(name: str) -> str:
    print(f"{name}：进入函数体")
    await asyncio.sleep(1)
    print(f"{name}：等待结束")
    return name


async def main() -> None:
    print("1. fetch_data 是协程函数：", inspect.iscoroutinefunction(fetch_data))
    coro = fetch_data("A")
    print("2. coro 是协程对象：", inspect.iscoroutine(coro))
    print("3. 即将执行 await")
    result = await coro
    print("4. 得到返回值：", result)


asyncio.run(main())
```

输出顺序是：

```text
1. fetch_data 是协程函数： True
2. coro 是协程对象： True
3. 即将执行 await
A：进入函数体
A：等待结束
4. 得到返回值： A
```

两条 A 的输出之间间隔约 1 秒。这说明创建 `coro` 时没有执行函数体，而执行 `await coro` 后才开始执行。

### 任务（Task）：让某个协程参与调度

在异步函数中还可以这样写：

```python
async def main() -> None:
    coro = fetch_data("A")
    task = asyncio.create_task(coro)
    result = await task
    print(result)
```

`asyncio.create_task(coro)` 将协程包装为 Task，并安排它运行。Task 负责推进协程，记录完成状态、返回值或异常；事件循环负责安排何时推进各个 Task。

直接 `await coro` 会在当前任务里执行并等待这个协程，**不会自动创建一个独立任务**。创建 Task 则可以让多个协程分别参与调度。下一节用两个任务说明区别。

## 5. 事件循环到底在做什么

事件循环是 `asyncio` 提供的调度机制，可以理解为不断重复以下工作的程序：

1. 从已经就绪的工作中选择一个来执行，例如推进某个 Task。
2. Task 中的协程等待一个尚未完成的异步操作时，暂时停止推进它，转而处理其他就绪工作。
3. 定时器到期、网络有数据等事件发生后，将对应的工作安排为就绪，之后恢复执行。
4. 如果暂时没有工作可运行，就等待新的事件，而不是一直执行某个等待中的协程。

下面是完整例子，使用 `asyncio.sleep()` 模拟两个查询的等待时间。在本例的默认调度下，A、B 的 Python 代码都在同一个线程上执行：

```python
import asyncio
from time import perf_counter


async def query(name: str, delay: float, start: float) -> str:
    print(f"{perf_counter() - start:.1f}s：{name} 开始，等待 {delay} 秒")
    await asyncio.sleep(delay)
    print(f"{perf_counter() - start:.1f}s：{name} 完成")
    return name


async def main() -> None:
    start = perf_counter()
    task_a = asyncio.create_task(query("A", 2, start))
    task_b = asyncio.create_task(query("B", 1, start))

    result_a = await task_a
    result_b = await task_b
    print(f"{perf_counter() - start:.1f}s：main 得到结果 {result_a}、{result_b}")


asyncio.run(main())
```

典型输出如下，时间可能略有偏差：

```text
0.0s：A 开始，等待 2 秒
0.0s：B 开始，等待 1 秒
1.0s：B 完成
2.0s：A 完成
2.0s：main 得到结果 A、B
```

逐步理解这次调度：

1. `asyncio.run(main())` 为独立脚本创建并运行事件循环，启动 `main`。
2. `main` 安排 A、B 两个 Task，然后在 `await task_a` 处等待。
3. 事件循环推进 A。A 打印后，在 `await asyncio.sleep(2)` 处暂停，并留下一个 2 秒后到期的定时器。
4. 事件循环推进 B。B 在 `await asyncio.sleep(1)` 处暂停，等待另一个定时器。
5. 约 1 秒后，B 的定时器到期。事件循环恢复 B，B 打印并返回。此时 A 和 `main` 仍在等待。
6. 约 2 秒后，A 恢复并完成；随后 `main` 可以继续执行。因为 B 早已完成，`await task_b` 可以直接取得结果。

**所以，`main` 虽然先等待 A，B 仍然能先完成：B 已经被安排成独立 Task，不需要等 `main` 执行到 `await task_b` 才开始。**

事件循环不会随意打断正在执行的 Python 代码。这里能切换，是因为 `asyncio.sleep()` 让当前任务暂停；如果换成 `time.sleep()`，线程会被阻塞，事件循环就无法及时处理其他任务和到期事件。

`await` 的含义仍然是“当前任务要等到结果才能继续下一行”。它允许等待期间运行其他任务，但若结果已经就绪，也不一定发生任务切换。[Python 协程与任务文档](https://docs.python.org/3.11/library/asyncio-task.html)、[事件循环文档](https://docs.python.org/3.11/library/asyncio-eventloop.html)。

## 6. 连续 `await` 与并发执行有什么区别

下面是可直接运行的对比示例：

```python
import asyncio
from time import perf_counter


async def fetch_data(name: str) -> str:
    print(f"{name} 开始")
    await asyncio.sleep(1)
    print(f"{name} 完成")
    return name


async def main() -> None:
    start = perf_counter()
    await fetch_data("A")
    await fetch_data("B")
    print(f"顺序等待：{perf_counter() - start:.1f} 秒")

    start = perf_counter()
    results = await asyncio.gather(fetch_data("A"), fetch_data("B"))
    print(f"并发等待：{perf_counter() - start:.1f} 秒")
    print(results)  # ['A', 'B']，结果顺序与传入顺序一致


asyncio.run(main())
```

第一种写法先等 A 完成，再开始 B，约 2 秒。第二种写法由 `asyncio.gather()` 安排两个协程并发运行，等待时间重叠，约 1 秒。

也可以在异步函数中先创建任务，再等待它们：

```python
async def run_tasks() -> None:
    task_a = asyncio.create_task(fetch_data("A"))
    task_b = asyncio.create_task(fetch_data("B"))
    await task_a
    await task_b
```

这里虽然也是两个 `await`，但 A、B 已经提前被安排为任务，因此可以并发运行。如果 B 必须使用 A 的返回结果，就应该先等待 A，不要强行并发。

## 7. 异步不等于多线程，也不等于并行计算

通常，一个事件循环在一个线程上交替执行多个任务，这叫并发；并行则强调多个任务在同一时刻实际执行，例如多个 CPU 核心同时计算。

因此，把耗时计算放进 `async def` 不会自动加速。长时间计算或直接调用阻塞函数，仍然会占住事件循环线程。

例如，在异步函数中直接写 `time.sleep(1)`，其他任务也无法在该事件循环上继续运行。休眠应使用 `await asyncio.sleep(1)`；必须调用同步阻塞 I/O 函数时，可以用线程转交执行：

```python
import asyncio
import time


def blocking_read() -> str:
    time.sleep(1)  # 模拟同步 I/O
    return "读取完成"


async def read_data() -> str:
    return await asyncio.to_thread(blocking_read)
```

`asyncio.to_thread()` 将同步函数放到工作线程中执行，适合转交阻塞 I/O；大量 CPU 计算通常需要考虑多进程等方式。

## 8. 在 FastAPI 和当前建表代码中怎么用

FastAPI 支持同步和异步路由：

- 使用支持 `await` 的数据库或网络库时，通常写 `async def` 路由。
- 使用同步阻塞库时，可以写普通 `def` 路由，FastAPI 会在线程池中执行该路由。
- 自己在异步函数中直接调用的普通工具函数，不会自动被 FastAPI 放到线程池。

例如，异步路由中的等待由服务器已有的事件循环管理：

```python
import asyncio
from fastapi import FastAPI


app = FastAPI()


@app.get("/demo")
async def demo():
    await asyncio.sleep(1)
    return {"message": "完成"}
```

因此，在 FastAPI 的异步路由或 `lifespan` 内直接使用 `await`，不要再调用 `asyncio.run()` 启动一个事件循环。

回到当前建表函数：

```python
async def create_db_tables() -> None:
    async with engine.begin() as connection:
        await connection.run_sync(Base.metadata.create_all)
```

`async with` 管理连接和事务的进入、退出，`await` 等待建表完成。`lifespan` 中的 `await create_db_tables()` 表示必须先完成建表，再执行到 `yield`，然后应用才开始接收请求。

后面的 `lifespan` 含有 `yield`，属于异步生成器函数；它与这里不含 `yield` 的协程函数不同，需要通过 `@asynccontextmanager` 适配为上下文管理器，不能直接写 `await lifespan(app)`。具体用法见[asynccontextmanager 装饰器](05-asynccontextmanager装饰器.md)。

## 9. 为什么 `create_async_engine()` 前没有 `await`

是否可以使用 `await`，取决于表达式返回的对象是否支持等待（例如协程、Task、Future），不能只看函数名或是否写了 `async def`。

`create_async_engine()` 是普通的工厂函数。调用它会返回一个 `AsyncEngine` 配置对象，因此这里不写 `await`：

```python
engine = create_async_engine(DATABASE_URL)
```

真正执行异步数据库操作时才使用 `await` 或 `async with`：

```python
async with engine.begin() as connection:
    await connection.run_sync(Base.metadata.create_all)
```
