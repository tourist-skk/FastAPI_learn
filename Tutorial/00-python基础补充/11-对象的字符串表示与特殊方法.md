# 11 · Python 对象的字符串表示与特殊方法

本篇从新闻项目 `Category` 模型中的 `__repr__()` 出发，学习 Python 如何让对象参与打印、格式化、比较、遍历和资源管理。示例按本项目 Python 3.11 环境编写。

先记住：**`__repr__` 偏向调试时识别对象，`__str__` 偏向向人展示对象。它们都必须返回字符串，但并不负责把对象转换成数据库记录或 JSON。**

相关基础：[08-ORM对象](08-ORM对象.md)、[04-上下文管理器](04-上下文管理器.md)、[10-星号与参数解包](10-星号与参数解包.md)。

## 1. 先区分类、对象、方法和内置调用

```python
class Category:
    def __init__(self, name: str):
        self.name = name

    def __str__(self) -> str:
        return f"分类：{self.name}"


category = Category("科技")
print(str(category))  # 分类：科技
```

| 写法 | 是什么 |
| --- | --- |
| `Category` | 类，用来描述和创建分类对象 |
| `category` | `Category` 的一个实例 |
| `category.name` | 对象的属性 |
| `__str__` | 类中定义的特殊方法 |
| `str(category)` | 调用内置 `str` 类型进行字符串转换，普通对象的转换会使用 `__str__` 协议 |
| `category.__str__()` | 显式调用这个特殊方法 |
| `category.str()` | 普通方法调用，只有自己定义了名为 `str` 的方法才存在 |

`self` 是当前实例。调用 `category.__str__()` 时，Python 会把 `category` 绑定为方法的 `self`，所以不需要再手动传入。

日常代码优先写 `str(category)`、`repr(category)`、`len(category)`，通过公开协议使用对象。[Python 内置函数与类型](https://docs.python.org/3.11/library/functions.html)

## 2. 什么是特殊方法？

`__repr__`、`__str__`、`__len__` 等前后都有两个下划线，通常叫作**特殊方法**、**魔术方法**或 **dunder 方法**。

它们是 Python 预先约定的接口：当对象参与某种语法或内置操作时，解释器会按协议寻找对应实现。例如，`len(obj)` 使用长度协议，`obj[key]` 使用下标访问协议。

| 命名形式 | 常见含义 |
| --- | --- |
| `name` | 普通公开名称 |
| `_name` | 按约定供内部使用，不是强制访问限制 |
| `__name` | 在类定义中通常触发名称改写，主要用于避免子类名称冲突 |
| `__name__` | Python 特殊名称，例如特殊方法或特殊属性 |

因此，`__repr__` 不是“因为有双下划线所以私有”。也不要随意发明 `__to_json__` 之类的名称，并期待 Python 自动认识它。

并非所有双下划线名称都是方法：`__dict__`、`__class__` 是属性，`__slots__` 是类配置；`__repr__()` 才是可调用的方法。[Python 数据模型](https://docs.python.org/3.11/reference/datamodel.html#special-method-names)

## 3. `__repr__` 与 `__str__` 的区别

### 3.1 同一个对象，两种表示

下面是**独立可运行的普通 Python 类**，用来学习语言行为，没有连接数据库。第 3～5 节标注“沿用示例”的代码都基于这个类和实例。

```python
class Category:
    def __init__(self, id: int | None, name: str, sort_order: int = 0):
        self.id = id
        self.name = name
        self.sort_order = sort_order

    def __repr__(self) -> str:
        return (
            f"Category(id={self.id!r}, "
            f"name={self.name!r}, sort_order={self.sort_order!r})"
        )

    def __str__(self) -> str:
        return f"分类：{self.name}"


category = Category(id=1, name="科技", sort_order=7)

print(repr(category))
# Category(id=1, name='科技', sort_order=7)

print(str(category))
# 分类：科技

print(category)
# 分类：科技
```

| 对比 | `__repr__` | `__str__` |
| --- | --- | --- |
| 主要目的 | 帮助开发者识别对象和关键状态 | 提供适合阅读的文本 |
| 常见内容 | 类名、字段名、关键字段值 | 名称、标题或简洁描述 |
| 常见入口 | `repr(obj)`、调试显示、`!r` | `str(obj)`、`print(obj)`、`!s` |
| 返回要求 | 必须是 `str` | 必须是 `str` |
| 是否必须手写 | 不必须，可继承默认实现 | 不必须，可继承默认实现 |

这只是设计目标，不是强制规定“用户永远看不到 repr”。日志、异常信息、调试器、容器展示等都可能间接显示它，因此要控制输出内容。

官方建议 `repr` 尽可能明确、信息充分；如果合适，可以写成类似构造表达式的形式，但不要求一定能重新构造对象。[`object.__repr__` 与 `object.__str__`](https://docs.python.org/3.11/reference/datamodel.html#object.__repr__)

### 3.2 `repr` 的输出不一定能交给 `eval`

下面两种调试表示都可以使用：

```text
Category(id=1, name='科技', sort_order=7)
<Category id=1 name='科技'>
```

第一种看起来像 Python 表达式，第二种明确表示这是描述文本。ORM 对象可能带有会话、关系和加载状态，打印几个字段本来就无法还原完整对象。

`repr` 也不是保存数据的格式；不要把“能打印出来”理解成“可以可靠地用 `eval` 还原”。

### 3.3 只实现一个方法时，会发生什么？

对于未额外改变继承行为的普通类：

| 类的实现 | `repr(obj)` | `str(obj)` / `print(obj)` |
| --- | --- | --- |
| 两者都没有重写 | 继承默认对象表示 | 默认 `__str__` 使用对象的 `__repr__` |
| 只重写 `__repr__` | 使用自定义 `__repr__` | 通过默认 `__str__` 使用自定义 `__repr__` |
| 只重写 `__str__` | 仍使用默认对象表示 | 使用自定义 `__str__` |
| 两者都重写 | 使用自定义 `__repr__` | 使用自定义 `__str__` |

默认对象表示通常类似 `<__main__.Category object at 0x...>`；具体模块名和标识部分会变化。

**回退有方向：默认 `__str__` 会使用 `__repr__`，默认 `__repr__` 不会反过来使用自定义 `__str__`。**

这解释了你当前模型只写 `__repr__()`，`print(category)` 仍然能显示分类信息的原因，前提是基类没有另外定义不同的 `__str__` 行为。

## 4. 打印、容器与 f-string 到底调用哪个？

### 4.1 常见调用对照

以下“默认格式化”指对象没有自定义 `__format__` 时的行为：

| 写法 | 使用的协议 |
| --- | --- |
| `repr(obj)` | `__repr__` |
| `str(obj)` | `__str__` |
| `print(obj)` | 取得对象的字符串表示，通常走 `str(obj)` |
| `print([obj])`、`repr([obj])` | 内置列表展示其中元素时使用元素的 `repr` |
| `print({"item": obj})` | 内置字典展示键和值时使用它们的 `repr` |
| `f"{obj}"` | 使用 `__format__("")`；默认实现转向 `str(obj)` |
| `f"{obj!s}"` | 先转成 `str`，再对字符串格式化 |
| `f"{obj!r}"` | 先转成 `repr`，再对字符串格式化 |
| `f"{obj!a}"` | 先使用 `ascii(obj)`，将非 ASCII 字符转义 |
| `f"{obj=}"` | 无额外转换和格式说明时，调试语法默认使用 `repr` |
| `"%s" % obj` / `"%r" % obj` | 分别使用字符串表示 / 调试表示 |

f-string 中的转换标记和格式说明是不同功能。[Python 字符串格式语法](https://docs.python.org/3.11/library/string.html#format-string-syntax)

### 4.2 为什么 `print(obj)` 与 `print([obj])` 不同？

沿用第 3.1 节：

```python
print(category)
# 分类：科技

print([category])
# [Category(id=1, name='科技', sort_order=7)]

print({"category": category})
# {'category': Category(id=1, name='科技', sort_order=7)}

print(f"{category!r}")
# Category(id=1, name='科技', sort_order=7)

print(f"{category=}")
# category=Category(id=1, name='科技', sort_order=7)
```

打印列表时，`print` 首先处理列表对象，列表再决定如何展示其中的元素。它不会逐个把元素交给 `print`。

同理，`print(str(category))` 打印的是字符串内容；交互式解释器中直接输入 `str(category)`，通常会看到字符串的调试表示，外面可能带引号。那不一定是字符串本身包含了引号。

### 4.3 `!r` 为什么适合放在模型的 `__repr__` 中？

```python
name = "科技\n快讯"

print(f"name={name}")
# name=科技
# 快讯

print(f"name={name!r}")
# name='科技\n快讯'
```

`!r` 让字符串的引号、换行转义等更清楚。`None`、数字、空字符串和字符串 `"None"` 也更容易区分。因此，在调试输出里通常写 `name={self.name!r}`。

### 4.4 `__format__`：更细的格式化协议

`format(obj, spec)` 和 f-string 中的 `:spec` 使用 `__format__`。下面是一个独立示例：

```python
class NewsCount:
    def __init__(self, value: int):
        self.value = value

    def __str__(self) -> str:
        return f"{self.value} 篇新闻"

    def __format__(self, format_spec: str) -> str:
        if format_spec == "":
            return str(self)
        if format_spec == "number":
            return str(self.value)
        raise ValueError(f"不支持的格式：{format_spec!r}")


count = NewsCount(12)
print(f"{count}")         # 12 篇新闻
print(f"{count:number}")  # 12
print(f"{count!s:>10}")   # 先转成字符串，再按字符串规则右对齐
```

`__format__` 也必须返回字符串。普通对象默认只支持空格式说明；不要因为实现了 `__str__`，就假设 `f"{obj:>10}"` 一定可用。希望按字符串对齐时，可以写 `f"{obj!s:>10}"`。

## 5. 返回字符串，而不是在方法里打印

下面是错误示例。代码只定义类；注释中的调用会报错：

```python
class BadCategory:
    def __repr__(self):
        print("Category")  # 错误：没有 return，实际返回 None


# repr(BadCategory())  # TypeError：__repr__ 返回了非字符串
```

正确的实现应 `return "Category"`。`print` 是副作用，返回值通常是 `None`。

以下写法也会出问题：

| 错误写法 | 原因 |
| --- | --- |
| 在 `__repr__` 中 `return {"id": self.id}` | 返回的是字典，违反字符串返回协议 |
| 在 `__repr__` 中 `return f"{self!r}"` | 再次调用自己的 `__repr__`，无限递归 |
| 在 `__str__` 中 `return f"{self}"` | 默认格式化又回到自己的 `__str__`，可能无限递归 |
| 用打印方法提交数据库事务 | 打印对象会改变业务状态，调试行为变得不可预测 |

好的对象表示应简短、稳定、便于识别，并尽量没有副作用。

## 6. 结合当前 `Category` ORM 模型

### 6.1 当前代码表达了什么？

你在 [models/news.py](../../toutiao_backend/models/news.py) 中编写了类似下面的方法：

```python
def __repr__(self):
    return f"<Category(id={self.id}, name={self.name}, sort_order={self.sort_order})>"
```

这里读取当前模型实例的三个属性，拼成一个调试字符串。它不创建数据库记录、不决定接口字段，也不会让 `Category` 变成字典。

如果参照它继续完善，可以在现有 `Category` 类中使用下面的方法片段，增加返回类型注解和 `!r`：

```python
def __repr__(self) -> str:
    return (
        f"<Category(id={self.id!r}, "
        f"name={self.name!r}, sort_order={self.sort_order!r})>"
    )
```

若另有面向人的展示需求，可以再增加：

```python
def __str__(self) -> str:
    return f"分类：{self.name}"
```

这几个片段放在已有模型类内部即可；不要为了套用第 3 节的普通类示例，直接覆盖 ORM 的构造方式或字段声明。

### 6.2 ORM 对象的打印应控制访问范围

普通 Python 属性通常只是取内存值，ORM 映射属性却可能带有加载行为。

- 优先展示少量关键标量字段，不遍历整个对象或所有关联对象。
- 不输出密码、登录令牌等敏感字段，也不把整篇新闻正文放进调试表示。
- 避免在 `__repr__` 中执行查询、提交事务或访问尚未加载的关系，例如 `self.news_list`。
- 即使是普通列，如果处于过期或延迟加载状态，访问时也可能触发刷新查询；异步 ORM 场景下，隐式 I/O 可能导致异常。
- 尚未写入数据库的对象，自动生成的主键可能为 `None`，调试表示应允许这种状态。

因此，上面的简单 `__repr__` 适合字段已经可用的对象，并不能保证在所有 ORM 加载状态下都不查询数据库。[SQLAlchemy 异步场景中的隐式 I/O](https://docs.sqlalchemy.org/en/20/orm/extensions/asyncio.html#preventing-implicit-io-when-using-asyncsession)

若只需要排查对象身份，可以使用下面的替代方法片段。`inspect` 放在模块导入区域，方法放在已有模型类中：

```python
from sqlalchemy import inspect


def __repr__(self) -> str:
    state = inspect(self)
    return f"<Category identity={state.identity!r}>"
```

它读取 SQLAlchemy 的实例状态而非关系字段。已持久化对象的身份可能显示为 `(1,)`；没有持久化身份的对象可能为 `None`。代价是调试信息更少。

### 6.3 `__repr__` 不是接口序列化协议

`str(category)` 和 `repr(category)` 返回的都是文本。FastAPI 的响应结构、Pydantic 模型的数据输出、SQLAlchemy 字段映射，各有各的规则。

普通对象的 `json.dumps(obj)` 不会因为实现了 `__repr__` 就自动成功。即使写 `json.dumps(obj, default=str)`，通常也只是得到一个 JSON 字符串值，不是期望的字段对象。

接口仍应明确使用响应模型或字段字典。相关区别见 [ORM 对象与字典、JSON](08-ORM对象.md)。

## 7. 创建、初始化、调用和清理

### 7.1 常见方法速查

| 操作 | 相关方法 | 关键点 |
| --- | --- | --- |
| 创建实例 | `__new__(cls, ...)` | 创建或返回实例；普通类通常不用重写 |
| 初始化实例 | `__init__(self, ...)` | 给已经创建的实例设置初始状态，必须返回 `None` |
| 把实例当函数调用 | `__call__(self, ...)` | 让 `obj(...)` 有具体行为 |
| 对象终结 | `__del__(self)` | 终结时机不应作为可靠资源管理手段 |

普通实例化过程可以简化理解为：

```text
Category(...)
    → __new__ 创建实例
    → __init__ 初始化实例
    → 得到实例
```

严格说，只有当 `__new__` 返回相应类的实例时，才会继续进行对应的初始化。日常业务类通常只需要写 `__init__`。[Python 实例创建与初始化](https://docs.python.org/3.11/reference/datamodel.html#object.__new__)

### 7.2 `__call__` 示例

```python
class TitleFormatter:
    def __init__(self, prefix: str):
        self.prefix = prefix

    def __call__(self, title: str) -> str:
        return f"{self.prefix}{title}"


formatter = TitleFormatter("[新闻] ")
print(formatter("学习 Python"))  # [新闻] 学习 Python
print(callable(formatter))       # True
```

`TitleFormatter(...)` 创建实例，`formatter(...)` 则通过实例的 `__call__` 格式化标题。可调用对象还能用于回调、装饰器和依赖注入。

### 7.3 `del obj` 不等于立刻执行 `obj.__del__()`

`del obj` 删除的是一个名称绑定；如果对象还有其他引用，它仍然可能存在。即使对象进入回收阶段，终结方法也不适合用来保证数据库事务、文件等资源按预期释放。

资源清理优先使用 `with`、`async with`、`try/finally` 或明确的 `close()`。[上下文管理器笔记](04-上下文管理器.md)

## 8. 比较与哈希：`==`、`is`、`set` 为什么不同？

### 8.1 比较协议

| 操作 | 对应方法 |
| --- | --- |
| `a == b` | `__eq__` |
| `a != b` | `__ne__` |
| `a < b`、`a <= b` | `__lt__`、`__le__` |
| `a > b`、`a >= b` | `__gt__`、`__ge__` |
| `hash(a)`、作为字典键或集合元素 | `__hash__` |
| `a is b` | 判断是否同一个对象，不能通过重写上述比较方法改变 |

表格表示相关协议，具体调度还会考虑另一侧对象和子类的优先级。`==` 可以由类定义值相等的规则，`is` 比较对象身份。自定义 `__eq__` 不会自动补齐所有排序方法。[Python 比较规则](https://docs.python.org/3.11/reference/expressions.html#comparisons)

独立示例：

```python
class CategoryLabel:
    def __init__(self, name: str):
        self.name = name

    def __eq__(self, other):
        if type(other) is not type(self):
            return NotImplemented
        return self.name == other.name


first = CategoryLabel("科技")
second = CategoryLabel("科技")

print(first == second)  # True：按名称比较
print(first is second)  # False：两个独立对象
print(first == "科技")  # False：没有实现与字符串的值比较
```

`NotImplemented` 是告诉 Python“我不支持与这种对象进行该操作”，解释器可以尝试另一侧或后备规则。它不是异常，也不是 `NotImplementedError`；不要写成 `raise NotImplemented`。

对于两个不同的普通对象，默认相等行为不会因为字段恰好一样就判断相等。ORM 中也不要简单认为“数据库主键相同”就必然等同于 Python 的 `==`，应明确自己需要比较身份、主键还是业务字段。

### 8.2 重写 `__eq__` 后，要考虑 `__hash__`

哈希用于字典和集合查找。必须满足：

```text
如果 a == b 为 True，则 hash(a) 必须等于 hash(b)。
相同哈希值并不意味着 a == b。
```

参与哈希和相等判断的状态，不应在对象作为字典键或集合元素期间变化。

上面的 `CategoryLabel` 重写了 `__eq__`，没有定义 `__hash__`，因此 Python 会使它不可哈希：`hash(first)` 或 `{first}` 会抛出 `TypeError`。这比让可变名称影响集合查找更合理。

可用不可变的简单值对象表示键，下面是独立示例：

```python
from dataclasses import dataclass


@dataclass(frozen=True)
class CategoryKey:
    id: int


names = {CategoryKey(1): "科技"}
print(names[CategoryKey(1)])  # 科技
```

对本例只有整数的字段，生成的相等和哈希行为可以配合使用。`frozen=True` 不会把对象引用的所有嵌套内容都变成不可变对象。

## 9. 容器协议：长度、真假、下标与遍历

### 9.1 常用方法

| 操作 | 方法 | 返回或行为要求 |
| --- | --- | --- |
| `len(obj)` | `__len__` | 非负整数 |
| `bool(obj)`、`if obj:` | `__bool__` | 必须返回 `bool` |
| `obj[key]`、`obj[start:stop]` | `__getitem__` | 按键、索引或切片取值 |
| `obj[key] = value` | `__setitem__` | 按键写入 |
| `del obj[key]` | `__delitem__` | 删除某个元素 |
| `item in obj` | `__contains__` | 判断成员关系 |
| `iter(obj)`、`for item in obj` | `__iter__` | 返回迭代器 |
| `next(iterator)` | `__next__` | 返回下一项，结束时抛出 `StopIteration` |

没有 `__bool__` 时，Python 尝试用 `__len__` 判断真假，长度为 0 则为假；两者都没有时，普通对象通常为真。

没有 `__contains__` 时，成员判断可以退回迭代等协议；没有 `__iter__` 时，一些对象也可以通过从索引 0 开始的 `__getitem__` 支持序列遍历。因此，对照表不是“缺了一个方法，所有相关操作就一定失败”。

### 9.2 用一个新闻标题集合串起来

下面是独立可运行的普通类：

```python
class NewsTitles:
    def __init__(self, titles):
        self._titles = list(titles)

    def __repr__(self) -> str:
        return f"NewsTitles({self._titles!r})"

    def __len__(self) -> int:
        return len(self._titles)

    def __getitem__(self, key):
        return self._titles[key]

    def __iter__(self):
        return iter(self._titles)

    def __contains__(self, title: str) -> bool:
        return title in self._titles


titles = NewsTitles(["学习 Python", "学习 FastAPI"])

print(len(titles))                # 2
print(bool(titles))               # True：通过 __len__ 判断
print(bool(NewsTitles([])))       # False
print(titles[0])                  # 学习 Python
print(titles[:1])                 # ['学习 Python']
print("学习 FastAPI" in titles)   # True
print(list(titles))               # ['学习 Python', '学习 FastAPI']
```

切片传入的是 `slice` 对象。本例直接交给内部列表处理，因此返回的切片也是列表，不是 `NewsTitles`。

`NewsTitles` 是可迭代对象，但它没有实现 `__next__`，不是迭代器。`iter(titles)` 返回的列表迭代器负责保存遍历位置，并在结束时抛出 `StopIteration`。每次调用 `iter(titles)` 都取得一个新的迭代器，可以重新遍历。[Python 迭代器教程](https://docs.python.org/3.11/tutorial/classes.html#iterators)

## 10. 运算与类型转换协议

### 10.1 运算符可以由对象定义含义

| 操作 | 常见方法 |
| --- | --- |
| `a + b` | `__add__`，必要时考虑另一侧的 `__radd__` |
| `a - b`、`a * b`、`a / b` | `__sub__`、`__mul__`、`__truediv__` 等 |
| `a += b` | 优先尝试 `__iadd__`；未实现或返回 `NotImplemented` 时退回加法协议 |
| `-a`、`abs(a)` | `__neg__`、`__abs__` |
| `int(a)`、`float(a)` | `__int__`、`__float__` |
| 用作整数索引、传给 `hex(a)` | `__index__`，要求无损表达为整数 |
| `bytes(a)` | 对自定义对象可使用 `__bytes__`，它返回 `bytes` |

带 `r` 的反向方法用于另一侧的运算实现，不能简单理解为把同一个结果倒过来。带 `i` 的原地方法也不保证一定修改原对象，它可以返回新对象。

只有类的业务含义适合某种运算时才实现它。新闻模型通常不需要定义“两条新闻相加”，不必为了学习把所有运算方法塞进模型。

### 10.2 ORM 中熟悉的 `==` 也是协议的应用

在 SQLAlchemy 中，`Category.id == 1` 的左侧是类上的映射表达式属性，它会构造 SQL 条件；已加载实例上的 `category.id == 1`，则通常是 Python 值比较。

因此，不同类型的对象可以对同一个运算符定义不同含义，运算结果也不总是普通的布尔值。这正是前面 [ORM 对象笔记](08-ORM对象.md) 中“模型属性与实例属性”的区别。

## 11. 属性访问、描述符与 ORM

### 11.1 属性操作也有协议

| 操作 | 相关方法 | 含义 |
| --- | --- | --- |
| `obj.name` | `__getattribute__` | 参与常规属性访问 |
| 常规属性查找失败后 | `__getattr__` | 可提供后备处理；不提供时应抛出 `AttributeError` |
| `obj.name = value` | `__setattr__` | 处理属性赋值 |
| `del obj.name` | `__delattr__` | 处理属性删除 |
| 类属性是描述符对象 | `__get__`、`__set__`、`__delete__` | 让该属性对象参与读取、写入、删除 |

`__getattr__` 不是每次访问属性都会执行；它通常是在常规查找失败后才被调用。重写 `__getattribute__` 或 `__setattr__` 则会影响大量正常访问，初学阶段应谨慎。

例如，在自定义 `__setattr__` 中再次写 `self.name = value`，会重复进入自己。普通类需要绕开该重写逻辑时，可使用 `object.__setattr__(self, name, value)`；ORM 已有自己的属性管理，不应随意接管。

描述符是 `property`、方法绑定以及许多 ORM 映射属性的基础。可以将其理解为“某个类属性本身也能决定如何被访问”，不需要为每个模型字段都手写这些方法。[Python 描述符指南](https://docs.python.org/3.11/howto/descriptor.html)

### 11.2 常见特殊属性不是方法

| 属性 | 用途与限制 |
| --- | --- |
| `obj.__class__` | 对象所属的类，日常也可以用 `type(obj)` |
| `obj.__dict__` | 对象的实例属性字典；部分对象没有它 |
| `SomeClass.__name__` | 类名 |
| `SomeClass.__module__` | 定义该类的模块名称 |
| `SomeClass.__mro__` | 方法查找时使用的继承顺序 |
| `SomeClass.__annotations__` | 类中声明的类型注解信息，不等于实例当前值 |
| `SomeClass.__slots__` | 声明实例属性布局的类配置，不是 JSON 字段列表 |

`vars(obj)` 通常取得对象的 `__dict__`，但不能把它当作通用接口响应。ORM 对象的字典可能含有内部状态，也可能没有尚未加载的字段。

## 12. 上下文管理与异步协议

| 语法 | 方法 | 用途 |
| --- | --- | --- |
| `with obj as value:` | `__enter__`、`__exit__` | 同步资源管理 |
| `async with obj as value:` | `__aenter__`、`__aexit__` | 异步资源管理 |
| `await obj` | `__await__` 等可等待协议 | 参与等待过程 |
| `async for item in obj:` | `__aiter__`、`__anext__` | 异步迭代，结束时使用 `StopAsyncIteration` |

同步上下文管理器的独立示例：

```python
class OperationLog:
    def __enter__(self):
        print("进入操作")
        return self

    def __exit__(self, exc_type, exc_value, traceback):
        print("退出操作")
        return False  # 发生异常时，不吞掉异常


with OperationLog() as operation:
    print("处理新闻")

# 进入操作
# 处理新闻
# 退出操作
```

`as operation` 接收 `__enter__` 的返回值，并不强制等于上下文管理器本身。正常退出时，`__exit__` 的三个异常参数都是 `None`；如果块中发生异常，它们用于描述异常。

`__exit__` 返回真值可以抑制块中的异常，因此处理事务时不能随便写 `return True`。数据库连接、会话和事务通常已由框架提供上下文管理器，使用它们即可。

异步方法与同步方法也是不同协议：定义普通 `__enter__` 不会让对象自动支持 `async with`。继续阅读 [上下文管理器](04-上下文管理器.md) 和 [asynccontextmanager 装饰器](05-asynccontextmanager装饰器.md)。

## 13. 为什么特殊方法通常要定义在类上？

Python 对许多特殊方法的隐式查找发生在对象的类型上，并不等价于普通的实例属性查找。因此，给某个实例临时赋一个同名属性，未必能改变内置操作的行为。

独立示例：

```python
class Box:
    pass


box = Box()
box.__len__ = lambda: 3

print(box.__len__())  # 3：显式实例属性调用可以成功
# print(len(box))    # TypeError：类型没有实现长度协议
```

正确方式是在 `Box` 类中定义 `def __len__(self): ...`。这也是为什么日常优先使用 `len(obj)` 等操作：它们遵守完整协议，而不只是机械地调用一个同名实例属性。[特殊方法查找](https://docs.python.org/3.11/reference/datamodel.html#special-method-lookup)

## 14. `dataclass` 能自动生成哪些方法？

普通的数据对象可以使用 `@dataclass` 减少重复代码：

```python
from dataclasses import dataclass, field


@dataclass
class CategoryInfo:
    id: int
    name: str
    sort_order: int = 0
    internal_note: str = field(default="", repr=False)


info = CategoryInfo(1, "科技", 7, internal_note="内部备注")

print(repr(info))
# CategoryInfo(id=1, name='科技', sort_order=7)

print(str(info))
# CategoryInfo(id=1, name='科技', sort_order=7)

print(info == CategoryInfo(1, "科技", 7, internal_note="内部备注"))
# True
```

默认情况下，`dataclass` 会生成 `__init__`、`__repr__`、按字段比较的 `__eq__` 等；它不会自动生成专门面向人的 `__str__`，因此这里的字符串表示通过默认行为使用生成的 `repr`。

`field(repr=False)` 只是不把该字段放进自动生成的调试表示，不会阻止读取字段，也不会自动把它排除在相等比较或序列化之外。本例的 `internal_note` 仍然参与比较。

排序方法需要按需开启 `order=True`；可变 dataclass 的默认哈希策略也不同于不可变值对象。具体生成规则见 [dataclasses 文档](https://docs.python.org/3.11/library/dataclasses.html)。

SQLAlchemy 有专门的 dataclass 集成方式，普通 `@dataclass` 不能直接等同于 ORM 模型配置。当前学习中先把“普通数据对象”和“数据库映射对象”分清楚即可。

## 15. 当前阶段的学习顺序与练习

不需要在每个类中实现所有特殊方法，按对象需要支持的操作选择即可。

| 优先级 | 建议掌握的内容 |
| --- | --- |
| 先掌握 | `__init__`、`__repr__`、`__str__`，以及 `print` / `repr` / f-string 的区别 |

可以依次完成这些练习：

7. 在 `OperationLog` 的 `with` 块中抛出 `ValueError`，验证退出方法会执行，异常仍会传播。
